What stays the same on every page.

Six things that set Vyre apart.

Each comparison starts from the same six points about how Vyre is built, so you can read them against any tool.

Your own server

Vyre runs on a server you own. Records, files, Flows and the history stay there.

People and agents together

Both are members of the same Space. They share chats, records, tasks and files.

Flows that repeat

A Flow is a stored list of steps. A person approves a version, and every run follows that version.

A yes before anything leaves

An email, a payment, a deletion or a published page waits at the Gate. An agent can ask. It cannot approve.

Sealed fields, use-only credentials

An agent sees a placeholder where a sealed value sits, and it uses a Vault credential without reading it.

Any model, your own computer

Claude, Codex, Grok and OpenRouter through your own accounts or keys. A session can run on a person’s own computer, in a sandbox.

How these pages are written

The other tools on these pages are good at what they were built for. Each page says what its kind of tool does well before it says where Vyre differs. About another product, a page says only what that product’s own public documentation says. Where we are not sure, the page describes the kind of tool. If a line is out of date, tell us in the repository.
