Vyre / Get started

Getting started

Put Vyre on your server.

The steps, in order. The Vyre app does most of them for you.

Vyre is not on npm yet, so your Mac installs the command line from a tarball on vyre.run, and the Mac app, Vyre Lumen, is built on your Mac rather than downloaded. The server install is checked against a published signature.

00

What you need

  • A server: a Linux machine you can ssh into with sudo (Docker is installed for you if it is missing, after you say yes), or a Mac that stays on.
  • An account with at least one of Claude, Codex, Grok or OpenRouter.
  • For Vyre Lumen on your Mac: Node 22.5 or newer (node --version).
01

Open the Vyre app

Open the Vyre app on your phone or Mac and choose Get started. Choose your Vyre name, save your recovery code, then create a space. For a space on a server you own, the app shows one line to run on it.

Open a terminal on your server as yourself, not as root, and paste the line. It looks like this:

$curl -fsSL vyre.run/i | sh

The installer asks before it installs anything, including Docker if the server has none. It sets Vyre up in /srv/vyre, checks what it downloads against a published signature, and starts it. On a Mac that stays on, the same line installs Vyre as a service that starts at boot. When it is done the terminal prints a QR and a long code.

02

Pair it from the app

  1. Scan or paste the code. On a phone, scan the QR your server printed; on a computer, paste the long code into the app.
  2. Check the three words. Your server’s terminal shows three words for each way in and asks you to pick the ones the app shows. Confirm only if they match.
  3. Finish setting up the space. Give it a look, connect your AI account and your tools, and pick a Kit or start empty. Each step has a Later.

Your server, your computers and your phone find each other through Vyre’s own network. There is nothing to install and nothing to sign in to.

03

Your Mac

Install the command line from the tarball, pair it with your server, then build Vyre Lumen:

$npm i -g https://vyre.run/box/vyre.tgz
$vyre up
$vyre capsule install

vyre up starts Vyre on this Mac and asks for your server’s pairing code. It shows three words; confirm they match the server’s screen, and approve with your passkey. vyre link on the Mac says when it is paired.

vyre capsule install builds Vyre Lumen on this Mac from the package; nothing is downloaded for it. If it says the Command Line Tools are not installed, run xcode-select --install, then run it again. Then open it with vyre capsule.

Option-Space opens Vyre Lumen from any app by default, with no extra permission. If you turn on Control twice instead from the menu-bar mark, grant Input Monitoring when it asks: macOS needs that permission to see the key. Contacts is optional, for contact results. More on the Mac page.

04

Your phone

Open the Vyre app and scan the code your server shows, or the one the Vyre app shows on a device you already use, or paste the long code. Both screens show the same three words, and the phone pairs only after you confirm them. Open Vyre from your Home Screen from then on. More on the phone page.

05

Windows

There is a Windows app for your Windows PC: a tray icon and an Alt+Space panel, and it updates itself. Its installer, VyreSetup.exe, comes with each release on GitHub. The app is not signed yet, so Windows may warn that the publisher is unknown: choose More info, then Run anyway. More on the Windows page.

!

What is not in 0.2.9

  • Real devices. Nothing has been walked on a real iPhone or Android yet, including Face ID pairing and the removed-phone wipe.
  • Screen Share. Screen Share (live view and computer use) comes in 0.3.1; Chrome control works today.
  • Mac server. The Mac server installer has not run on a real Mac yet.
  • Home routers. Home-router NAT is untested: a direct path through a home router has not been tried, and the relay carries the connection when there is none.
  • Phone notifications. Notifications when the phone app is closed: only web push today. Native push needs Apple and Google push accounts, which are not set up.
  • Models. Only the answer fan-out across models is proven; per-model plan and diff blocks are not.
  • Chrome. Parallel tabs read within one Chrome; a tab for each agent is not built.
  • Scale. Idle sessions do not sleep under memory pressure yet, and there is no fair-share scheduler.
  • Windows. The Windows app is not code-signed, and the first Windows install is not signature-checked.
  • The Mac app is built, not downloaded. There is no signed Mac download yet; vyre capsule install builds it on your Mac.
  • npm. npm install -g vyre works once the package is published. Until then, use the tarball URL.

More detail: Known gaps. Where this is going: Direction.

?

If something goes wrong

  • The page says the code expired, or two servers used it: press Start again for a new line.
  • The words do not match: press They don’t match, then start again. It means the line was not run on your server.
  • On the server: vyre status, vyre logs, and docker compose -p vyre ps.
  • Start over on a Linux server (keeps your data): curl -fsSL https://vyre.run/install.sh | sh -s -- --uninstall, then set up again. Add --purge to delete the vault, sign-ins and projects too.
