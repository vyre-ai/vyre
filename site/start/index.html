Vyre / Get started

Getting started

Start with your name.

Reserve your name, put the Vyre app on your computer, and the app does the rest.

The Mac and Android apps are not signed with a store or Apple identity yet, so you install them from the file (sideload). Every file in a release is checked against a published signature.

00

What you need

  • A Mac or a Windows PC for the app.
  • An account with at least one of Claude, Codex, Grok or OpenRouter.
  • To add a server: a Linux machine (a cloud machine is fine) or a Mac that stays on. With Records, which is recommended, it needs 8 GB of memory (4 GB at the least); without Records, 2 GB.
  • To join a team: the invite your team sent you.
01

Reserve your name

Open vyre.run/setup, type the name you want and press Reserve this name. The page shows a code that starts with VYRE. Copy it. It is held for you for 24 hours and works once.

02

Install the app

Mac: download Vyre-aarch64.dmg (Apple silicon) or Vyre-x86_64.dmg (Intel), open it and drag Vyre to Applications. Open it once; if macOS says it cannot check the app, choose Open Anyway in System Settings, Privacy and Security. More on the Mac page.

Windows: download VyreSetup.exe from the latest release and run it. If Windows warns that the publisher is unknown, choose More info, then Run anyway. More on the Windows page.

03

Paste the code

Open the app, choose Start and paste the code. The app makes your key on this computer and shows a recovery code once. Keep it somewhere only you can reach.

04

Choose how you will use Vyre

  • Join a team. Paste your team’s invite. You run on their server and need none of your own.
  • Add a server. A machine of your own that stays on: a Linux server, or a Mac. Choose With Records (recommended) or Without Records (a small server).
  • Use My Home (Mac only). Vyre runs on this Mac while it is awake. Add a server later and everything moves across.
05

Add a server

The app shows one line. Open a terminal on the server as yourself, not as root, and paste it. It looks like this:

$curl -fsSL vyre.run/i | VYRE_CODE=… VYRE_STORE=auto sh

On a Mac that stays on, the app shows the Mac line instead, and the Mac asks for its password once so Vyre can start when the Mac starts. The line works once and expires in 30 minutes.

The installer checks the release’s signature and sets Vyre up. The server pairs itself. The app finds your server and finishes pairing. You can also open the server's setup page and paste the code the app shows. The page locks after pairing.

06

Add your phone

From the app, choose Add your phone. On Android, download Vyre-android.apk on the phone and open it; allow installs from your browser or Files app when Android asks. On iPhone there is no App Store app yet: you build the app and install it with Xcode. Scan the code from your computer and check that both screens show the same words. More on the phone page.

!

What is not in 0.5.1

  • Real devices. Nothing has been walked on a real iPhone or Android yet, including Face ID pairing and the removed-phone wipe.
  • Screen Share. Screen Share (live view and computer use) comes later; Chrome control works today.
  • Mac server. The Mac server installer has not run on a real Mac yet.
  • Home routers. Home-router NAT is untested: a direct path through a home router has not been tried, and the relay carries the connection when there is none.
  • Phone notifications. Notifications when the phone app is closed: only web push today. Native push needs Apple and Google push accounts, which are not set up.
  • Models. Only the answer fan-out across models is proven; per-model plan and diff blocks are not.
  • Chrome. Parallel tabs read within one Chrome; a tab for each agent is not built.
  • Scale. Idle sessions do not sleep under memory pressure yet, and there is no fair-share scheduler.
  • Windows. The Windows app is not code-signed, and the first Windows install is not signature-checked.
  • Sideloaded apps. The Mac app has no Apple Developer ID signature yet and the Android app is not on a store, so you install both from the file.
  • npm. npm install -g vyre works once the package is published. Until then, use the tarball URL.

What comes next, by version: the roadmap. Where this is going: Direction.

?

If something goes wrong

  • The app says the reservation code is not valid: it lasts 24 hours and works once. Reserve the name again on vyre.run/setup.
  • The app says the line expired, or two servers used it: press Start again for a new line.
  • The setup page will not take a code: the server is already paired, or that code was used. In the app, start again for a new line.
  • On the server: vyre status, vyre logs, and docker compose -p vyre ps.
  • Start over on a Linux server (keeps your data): curl -fsSL https://vyre.run/install.sh | sh -s -- --uninstall, then set up again. Add --purge to delete the vault, sign-ins and projects too.
