Getting started

Put Vyre on your server.

The steps, in order. The setup page does most of them for you.

Vyre is not on npm yet, so your Mac installs the command line from a tarball on vyre.run, and the Mac app, Vyre Lumen, is built on your Mac rather than downloaded. The server install is checked against a published signature.

00

What you need

  • A server: a Linux machine you can ssh into with sudo (Docker is installed for you if it is missing, after you say yes), or a Mac that stays on.
  • A Tailscale account. The free plan is enough. Tailscale is required.
  • An account with at least one of Claude, Codex, Grok or OpenRouter.
  • For Vyre Lumen on your Mac: Node 22.5 or newer (node --version).
01

Open the setup page

Go to vyre.run/setup and choose A Linux server or A Mac that stays on. The page gives you one line with a one-time code in it. The code works for an hour and for one server.

Open a terminal on your server as yourself, not as root, and paste the line. It looks like this:

curl -fsSL https://vyre.run/i | VYRE_CODE=<the code on the page> sh

The installer asks before it installs anything, including Docker if the server has none. It sets Vyre up in /srv/vyre, checks what it downloads against a published signature, and starts it. On a Mac that stays on, the same line installs Vyre as a service that starts at boot. The setup page follows the install as it happens.

02

Finish in your browser

  1. Check the words. Your server's terminal prints four words. The page shows four words too; press These match my server's terminal only if they are the same. If they are not, press They don't match.
  2. Name your server. Pick the address you will reach it at, you.vyre.run, or use your own domain.
  3. Save your recovery code. It is shown once. If you ever reinstall, it takes this address back.
  4. Sign in to your AI. Claude, Codex and Grok each sign in on the provider's own page; Vyre never sees your password. One is enough to go on, and you can add more later.
  5. Connect Tailscale. Press Connect, sign in on Tailscale's page, and the setup page notices when your server joins. If your Tailscale is a work network, the page warns that your company's admins can reach the server.
  6. Add your phone (you can skip this). The page shows a ring to scan with your phone.
  7. Open your server. Your server has its own address. Open it once from the setup page: it asks for your fingerprint, face or a security key, and that makes you its owner.

Your address only opens from your own devices on your tailnet. Put Tailscale on your Mac and your phone (tailscale.com/download) and sign in with the same account.

03

Your Mac

Install the command line from the tarball, pair it with your server, then build Vyre Lumen:

npm i -g https://vyre.run/box/vyre.tgz
vyre up
vyre capsule install

vyre up starts Vyre on this Mac and looks for your server on your tailnet (the Mac must be signed in to Tailscale). It asks the server to pair this Mac and prints a code; approve it in your Deck on your phone, or on another computer on your tailnet, with your passkey. vyre link on the Mac says when it is paired.

vyre capsule install builds Vyre Lumen on this Mac from the package; nothing is downloaded for it. If it says the Command Line Tools are not installed, run xcode-select --install, then run it again. Then open it with vyre capsule.

Option-Space opens Vyre Lumen from any app by default, with no extra permission. If you turn on Control twice instead from the menu-bar mark, grant Input Monitoring when it asks: macOS needs that permission to see the key. Contacts is optional, for contact results.

04

Your phone

Install Tailscale on your phone and sign in with the same account. Then scan the ring the setup page shows, or open your server's address in the phone's browser and add Vyre to your Home Screen. The phone shows your server's name and fingerprint and pairs only after you tap Pair. Open Vyre from your Home Screen from then on.

05

Windows

There is a Windows app for your Windows PC: a tray icon and an Alt-Space panel, and it updates itself. Its installer, VyreSetup.exe, comes with each release on GitHub. The app is not signed yet, so Windows may warn that the publisher is unknown: choose More info, then Run anyway.

!

Known gaps

What is not in 0.2.0

  • Interactive artifacts in Safari. On a Mac or an iPhone, a page that navigates itself can be sent your sign-in cookie. A fix comes in 0.2.1. Until then, open interactive pages only from agents you trust.
  • Terminal commands. Touch ID prompts for terminal commands that need them come in 0.2.1.
  • Chrome. API-first routing and parallel tabs come in 0.2.1.
  • Two models at once. "Give it to two" and per-provider blocks for plans and diffs come in 0.2.1.
  • Teams. Spaces, memory rollover and putting idle sessions to sleep come in 0.2.5.
  • The Mac app is built, not downloaded. There is no signed Mac download yet; vyre capsule install builds it on your Mac.
  • npm. npm install -g vyre works once the package is published. Until then, use the tarball URL.

More detail: Known gaps.

?

If something goes wrong

  • The page says the code expired, or two servers used it: press Start again for a new line.
  • The words do not match: press They don't match, then start again. It means the line was not run on your server.
  • On the server: vyre status, vyre logs, and docker compose -p vyre ps.
  • Start over on a Linux server (keeps your data): curl -fsSL https://vyre.run/install.sh | sh -s -- --uninstall, then set up again. Add --purge to delete the vault, sign-ins and projects too.
