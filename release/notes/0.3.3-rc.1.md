This is a release candidate for Vyre 0.3.3, for design partners to try before the final. It adds a way to run a chat on your own computer, publishing from a preview, signing from inside Vyre with one yes, outside agents, and a calmer idle server.

## Your computer and your chats

- **Run a chat on your own computer.** Turn on "Run on this computer" and the chats you start there run on that computer, with Vyre's tools. The chat says so in one quiet line ("This chat borrowed your Mac. It can reach the AI provider and nothing else."). One switch is the one yes; there is no approval per chat.
- **If your computer goes to sleep, the chat moves to the server** and says why. It does not stop.
- **Long tool calls on a Mac** can run for minutes instead of timing out after 25 seconds.
- **Files in a message.** Pick, paste or drop a file into a chat and the assistant can read it. Each file an assistant changed can be undone one at a time.
- **Context cards.** When your own words name a record exactly, the assistant hears what is on it.
- **A new Mac shows one "Get started" card** (add your phone, create your assistant) instead of a stack of banners.

## Publish

- **Publish from a preview.** A preview of a folder of files has a Publish button. A folder with a React page publishes as the preview shows it.
- **An app with a server.** A folder with a Dockerfile publishes as a running app. Visitors' WebSockets reach it. It runs on servers made by the Linux installer.
- **Your own address for public pages**, for example sign.yourfirm.com.
- **Secrets go through the Vault.** A published app's secrets are released by a grant, not pasted into the folder.
- **Make a repo from a folder.** A connected GitHub account can create a repository for a folder and send the first commit.

## Signing and Documents

- **One yes covers the whole signing**, not four. Both signing emails go out on the same yes.
- **A document nobody has signed** shows as a quiet row in Needs you. A signer who declines is no longer silent.
- **A signer sees your firm's page**, not the engine's logo. The link to a signed copy does not expire by default.
- **PDF works with no setup** on a server with Records, and there is a PDF converter in Apps for servers without it.

## Flows

- **Parallel lanes, sub-flows, business hours, holidays and what to do after downtime.** The Flow page draws them the way they are read.
- **Try it on last week.** Replay a Flow against the real triggers of a past window before you turn it on.
- **A Flow holds references, never values.** Saving a Flow with a key or password written into a step is refused.
- **Each Flow shows how it is doing** in the list (last run, what went well this week, what needs you, the next time), and a banner on its page when it is red. The approval card says what the Flow does before you approve it.
- **Finished runs shrink to one line** after the number of days you choose (90 by default).

## Vault

- **A Vault that reads as words.** One Add button (login, API key, secret, SSH key, bring in from another app), names shown as you write them.
- **"Used by" on every credential** lists the modules, watchers and Flows that use it. A credential can be linked to a record or a project.
- **Shared vaults work from your own devices**: create, invite, manage.
- **A login that ran out** is a card in Needs you that says what to do.

## Outside agents

- **Vyre is the home base for agents that live elsewhere.** Register an agent, give it one project's memory or files, and it comes in through a single address. A Vault pass is one kind of outside agent. New token, 30 more days keeps an agent for longer.

## Phone, relay and the idle server

- **The live screen works on a phone away from your server**, through the relay.
- **An idle server does almost no work.** The Flows timer sleeps until the next wake, and a box no longer recomputes its status every minute. A server with nothing to do stays quiet.
- **A backup carries the Drive of every space on the box.**

## Fixes

- A chat that moves to the server when its computer goes away no longer fails with an error; it starts again on the server and carries on.
- Security: a visitor to a published app's public page no longer receives the server owner's session. An agent inside your own command line is held to a credential's scope. A held item's approver is the person who asked.

## Known issues

- To be filled from the last full run before the tag. Anything red there that is not install, pairing, update, data loss, security or a person's main path is listed here by name.
- Updating a server that is on 0.3.0 can roll back: a Watchers step was added in the wrong place, so the update refuses to start Watchers and goes back. It is being fixed and will be in the final. Update from 0.3.1 or later, or wait for the final.
- The install walk does not yet cover inviting a second person to a team space or a second person joining from their own app on a server made by the installer. Both work on the daemon walk.
- The iPhone, Mac and Android apps are installed by hand (they are not in the stores). iPhone installs need the sideload script.
