Vyre 0.3.3-rc.1 is a release candidate on the beta channel, for testing before 0.3.3. Do not put a team on it yet: the items under Known issues are open.

## What to test

- A team in one Space: an owner names the server's Space, members join with their own identity, Records are shared, each member has their own chats.
- A project started from a library template: an assistant the owner adds is a member of its Space from the moment it is made, so the template's tasks for that assistant are created.
- The vault: a member cannot list, read, change or lock the owner's vault, and an AI session sees only the vault items it was granted. A request from an assistant says "asked by your assistant, not by you".
- AI sessions start on a server with Wink on (0.3.1 could not start one there).
- Updating from 0.3.1 with `vyre update` as a normal user keeps you signed in.

## Fixed since 0.3.1

- A member's AI turn is refused when the member has no AI sign-in of their own; the owner's sign-in is not used for it. Two ways around this remain, see Known issues.
- An installed app refuses a program path named by the server.
- Codex and Grok give one answer per turn.
- Records field names that Records reserves no longer stop a project from being created, and a failed Records step is retried.
- Lumen on a Mac no longer quits when the server sends a deeply nested event. It could exit shortly after a question to an assistant.

## Known issues

- On a running team chat, a member can still have a turn run on another person's AI sign-in by attaching a picture, or by mentioning a provider without naming an account. Fixed in rc.2.
- With about nine sessions at once the server can stall. Fixed in rc.2.
- Before the owner has chosen a Vyre name, a member's paired device is treated as the owner's. The app makes the owner choose a name before a team or an invite can exist, so the normal path does not reach it. Fixed in rc.2.
- First install with Records: about 13 minutes from Records being up until every module's record types exist and work tools answer. Until then the app says it is waiting for the records.
- A member's first chat after a pause takes 17 to 22 seconds. Cause not found yet.
- An assistant made before this release is not added to its Space by the update: its template tasks stay skipped until the owner starts a chat with it once, or runs `vyre space add-agent <space> <name>` from the server's terminal. That command does not work from the app yet.
- If an assistant is deleted and another is made under the same name, the new one is seated in the old one's chats and can pick up its open tasks. Permissions are not inherited.
- A project started from a template whose assistant does not exist comes up with those tasks skipped. The app says so once; nothing on the project itself says it.

## Updating

This release is on the beta channel only. A server on the stable channel stays on 0.3.1.
