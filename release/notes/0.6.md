Vyre 0.6 makes Flows something you can build, watch and stop from the app, gives each record the privacy you set, and lets an agent keep working with the access it was lent.

## What's new

### Flows

- Every step can say what happens if it goes wrong. "If something goes wrong" sets how long one try may take, how many tries, how long to wait between them, which errors are tried again, a check that the work is right, and the steps to run if it still fails. The Flow itself has "If the run fails" steps too.
- A Flow has a settings card: its description, how many runs at once, one at a time per key, when a quiet run counts as stuck, what it may send, and what it hands back to a Flow that started it.
- More of the engine is in the editor. A step can update several fields, ask about a record, hand a task over by a template, compare with "contains" and with a real yes or no, loop over any list with a limit you choose, and call a web address with a query, headers and a HEAD check. Any module action, and a connection's named operation, can be a step.
- A date and time picker, one for the whole app, used by Wait steps, date fields and records. A day you pick stays that day in every time zone.
- Text in a step is easier. Write a brace you want to keep, print a list or a date the way people read it, and use the run's own number, the Flow's name, the approver, the starter and the Space name.
- Every event is choosable as a trigger, a trigger can carry a condition, and Make a document maps its placeholders in a panel.
- Stop a run from its page. A run that is paused, failed or waiting can be stopped; it is kept, marked stopped, and what it waits on is withdrawn.
- Saved tests on a Flow's page: keep a run as a test, run the tests, remove one.
- An agent step has a deadline. When the time passes the agent loses its rights on that task, anything it held for a yes is discarded, and nothing is sent.
- One chat per Flow. A person writes in it and the Flow's agent wakes for them, as them, with the Flow and its recent runs in front of it.
- A teammate who is not an owner can read a Flow's description, its runs and the connections it uses, for a Flow they made or one shared with them.
- Agents and scripts can do the same from outside the app: the tool that edits a Flow reaches failure paths, and sets what a Flow sends and returns.

### Records

- Per-record privacy. A row of a record type your Space made, linked to a project, is read only by that project's team and the people who run the Space. Search, totals, lists, links between records and the activity feed follow the same rule.
- Write-once fields: the first value stays, and a later change is refused in words that name the field. A total can be added up from the records that point at a record.
- Paging never says more rows follow when the rest are rows you may not read.
- Who changed what: the server keeps an audit of changes to records for the people who run the Space. The screen for it comes later.
- Email can carry CC, BCC and files. A Flow's send step takes attachments from a record.

### Agents

- An agent woken for a task can use the connections its approved Kit names, for that task only, and only from a person who holds them. The loan ends with the task.
- A member can add their own AI account with a token. It stays in their own vault.
- Standing permissions for agents are in the server: what a person approved once for a kind of action can cover the repeats, within limits. The screens for them come later.
- Waking an agent is harder to misuse.

### Security

- On the phone, Face ID signs only what the phone can read, and the prompt shows the phone's own words, not text the page chose.
- A reference to a record is read by its type definition, not trusted by the first word of its name.
- A vault wipe finds the sealing process from the folder's own record, so a sealing process that has only just started can no longer slip past it.
- An unreadable tool caller is refused in one place, and the unused mobile caller label is gone from the tools' lists.

## Fixed

- The memory line in the 0.5.1 notes credited a rework that was reverted. The saving in startup memory comes from the startup flags.
- The touch targets that were too small on a phone are 44 high: small buttons and chips you can press.
- The event log no longer holds the whole app while a long backlog drains, and a caller that waits for it waits for the whole drain.
- Sample data in the app reads as a design studio, not a law firm.

## Updating

A Linux server updates from Settings, or with `vyre update`.

The Mac app: download the new dmg from the release and replace the app.

## Security notes

- Per-record privacy closes the known gap from 0.5: a member could read every row of a record type the Space defined itself, even when the row was linked to a project they were not on.
- An agent's deadline ends its rights on the task, not only its turn. What it still held for a yes is discarded.
- Connections lent to an agent are the approver's own: a connection the approver cannot use is refused whatever the Kit names.
