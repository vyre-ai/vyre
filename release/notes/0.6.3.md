Vyre 0.6.3 makes Vyre run on your own AI accounts, everywhere. Every chat, agent, Routine, Watcher and Flow runs on the AI account of the person it's for, with any provider. Agents set up their own Routines and Watchers when you ask, the Vault works like a shareable .env, and chat, Home and Records open at once.

## What's new

### Your own AI, everywhere

- Every AI turn runs on the account of the person it's for: the asker in a chat, the person who asked for a Routine or Watcher, a Flow's chosen accounts, the person who moved a record into a stage. Your account is never used for someone else, and a member's never for anyone but them. With no account, Vyre says so plainly.
- Settings > AI accounts is one list: Claude, Codex, Grok, OpenRouter and any OpenAI-compatible service, treated the same, with their real marks. Members add their own sign-ins and keys, and can have one sign-in per provider.
- One model picker everywhere, showing only the models your own accounts can run, with their real names, context size, price and abilities. Effort shows only for models that have it.
- In a chat, your model pick is yours alone. Switching provider keeps the whole conversation and its tool results.
- A Flow with AI steps has an AI accounts tab: a main account and a fallback. The fallback answers when the main one is out of credits, rate limited, signed out or down, and the run says which answered and why. Flow AI steps run on Claude, Codex and Grok sign-ins as well as keys.

### Agents

- Routines and Watchers belong to an agent and are made by asking it in chat. A Routine runs on a schedule; a Watcher wakes the agent when something new appears. Both run for the person who asked, on their own account, and show on the agent's page and beside its chats, with Pause, Resume, Run now and Delete.
- Each agent's computer has a Vyre wallpaper with its name, a Mac-style dock (Chrome, Terminal, Files), and a Vyre new tab page. Agent computers work on a new server with no setup: pressing the sleeping screen wakes it, and creates it the first time.
- An agent's folder lives on its computer: Files, the Terminal and Chrome all see the same files.

### Vault

- An item is a name plus fields, like a block of an .env file (GHL_API_KEY, GHL_LOCATION_ID). Paste from .env, pick an app, or start blank. Field names are case-insensitive; values are kept exactly as typed.
- Mine and Shared, search by field name, Copy as .env, and plain access levels: Can use it without seeing it, Can see it, Can change it. Rare features moved to Advanced.
- Agents use keys by placeholder ({{vault:Item.FIELD}}): Vyre fills them in on the server, sends them only to websites the item allows (the first new website asks you once), and hides them in replies. A model never sees a secret.

### Flows and Playbooks

- A webhook trigger is one address with Copy and Send a test; the secret is made for you. Signature checks are under Advanced. Forms post to the same address.
- Each Playbook stage is a Flow that starts when a record enters the stage. One engine, one task list.

### Chat, Home and Records

- A message that fails stays as "Not sent" with Retry; Retry never sends twice.
- Home, the Chat list and Records draw your last view at once and refresh behind it.
- Records: delete with Undo and a Bin, a real "Seal this field", Add a column that appears at once, New task that saves, record ids that are made for you and can't be edited, and members can work with records in Spaces they joined.
- The chat header has a Runs on switch, mentions show names, threads are named from their first message, and each agent has one row in the sidebar.

### People and Spaces

- A Space menu, an account menu under your face, and a profile per Space with a photo you crop in a circle.
- Unlock and sign-in work by keyboard alone.
- The Mac app lists its server on your Space's address by itself, and says why when it can't.
- GitHub sign-in works on the web and in the Mac app.

## Fixed

- Chats on the Mac app keep one chat key, so private chats open.
- Dark menus are readable, the welcome and unlock screens read in dark, and half-built Settings pages are hidden.
- web.vyre.run refreshes without a 404.

## Security

- No person, no agent work: anything with no person behind it starts no agent and spends no one's account.
- A member's chat with an agent acts as that member, never the owner; helpers, teammate requests, Kit stages and edited schedules act as the person behind them.
- Vault placeholders: allowed websites only, the whole host shown on approval, at most five pending asks per agent, compressed replies refused, wide redaction, and a use limit per item.
- Webhook addresses use a 32-byte token compared in constant time.

## If you installed 0.6.2

Update your server and the Mac app. Your schedules and teammate duties made before this release are paused with a note if Vyre can't tell who they run for; turn each one on to run it as you.

## Known gaps

- On a web session with no phone or passkey set up, Vault values can be revealed without a second confirmation (by the owner's choice until Apple signing).
- An agent's chat sessions don't run inside its computer yet; it works its computer through tools.
- Members see only "the account's default" in a Flow's model picker.
