Vyre 0.5.4 is the release 0.5.3 was meant to be: the same first run on the web, the Mac app and the Windows app, and it retires the install that ran only on one computer.

0.5.3 was tagged but never published. The release's install proof failed on its own test browser, which had no Ed25519 in its web cryptography. Nothing in the app was wrong. 0.5.4 has everything in 0.5.3, and the proof now uses a browser that has it.

## What's new

- **A new first run, the same everywhere.** You create your identity with a username, a master password and a recovery key. Then you join a space or create one. Creating one gives you a single install command with a one-time code in it. Run it on your server and the server pairs to you on its own. There are no four words to compare, no typed codes and no "run only on this computer" choice. You are ready when the app says your space is online.
- **Your username and master password.** One master password unlocks your identity and your personal vault. The recovery key is shown once. Your username has an address at vyre.run/u/name. The app locks itself after a while and asks for the master password when you come back.
- **Sign in from any device.** On a phone or another computer, enter your space address, your username and your master password. You can use GitHub in place of the username once you have linked it. Your master password stays on your device. Signing in sends a signature made with a key derived from it. The server keeps only a public key and your password-protected keys, so someone who stole the server's files could still try to guess a weak password offline. That is why the password must be at least 12 characters and is stretched with Argon2id.
- **A card for every new sign-in.** When someone signs in to your account on a new device, your other devices show a card. Choose "Not me" and that device is signed out.
- **Invite links that work anywhere.** A link to join a space looks like vyre.run/i/token. It opens in the app or on the web, and it shows the space and the role before you accept.
- **Vyre on the web.** The app on the web is now web.vyre.run. It is the same app as on the Mac and Windows, with the same first run. app.vyre.run sends you there.
- **Run on your own computer.** In Settings, Computer, choose whether a session may run on this computer: Always allow, Ask or Never. If your computer goes quiet, the server takes the session and continues from the last saved turn.
- **Group chats run on the server.** A chat with more than one person always runs on the space server. If you add a person to a chat that was running on a computer, Vyre says so in one line and moves it first.
- **No Tailscale.** Vyre no longer uses Tailscale for the Mac's outbound path or for its vault passes. Passes are tied to the holder's key and a signed, single-use request.
- **One identity can own more than one server.** Each server adopts you from its own install line.
- **A space vault with a rotating key.** The key rotates when someone leaves, so they cannot open it afterwards.
- **Security fixes.** Closed: pairing by a different server than yours, a vault secret sent to the wrong site, linking a GitHub account that GitHub did not confirm, and a chat message never resolves a vault, Drive or GitHub chip or a #Name as the owner.
- **Old setup flows are gone.** The typed codes, the four-words check, the "Solo" mode, the old Install screen and the QR codes in invites are removed. Adding another device is a sign-in.
- Chat shows which capabilities are on for a thread, on every surface.
- The Windows app asks with the same summary the Mac app shows, including a yes that names the card. It tries Windows Hello, then the TPM. If Hello cannot make the key, the app asks before it uses a software key. A Hello prompt on each signature has not been shown on a real PC yet, so that key is still held and the app asks in its own window first.
- An assistant can ask to enrol a Windows computer or to change how this computer runs. A change to people, devices or vault access waits for your one tap. The card that adds a device names that device, its type, its key fingerprint, and who asked. Nothing changes until you approve. An assistant never receives a vault value, including after you approve. Using the app yourself does not wait for that tap.

## Known gaps

- On a computer that runs its own Vyre (a Mac with a local Vyre, not the web, Windows or a Mac app with no local Vyre), Create a space pairs the server but does not publish the space's name in the directory, so `<name>.vyre.run` does not yet answer a sign-in from another device. The web, Windows and Mac apps with no local Vyre publish it. Fixed in the next release.
- GitHub sign-in from another device works once the relay (with its GitHub sign-in key) and the names directory are deployed. Until then GitHub sign-in refuses with a plain message, and username and master password work.
- An assistant on the command line that asks to create a person gets an approval card instead of a refusal. Nothing runs without your tap, and a password an assistant supplies is refused.
- In a chat, vault, Drive and GitHub chips and #Name stay as typed text and are not resolved yet.
- A computer still running Vyre 0.5.2 can, rarely, end a session that has just moved back to it, when its old stop arrives late. Update the computer to 0.5.4 to close it.

## Signing

A published Mac app is Developer ID signed and notarized only when the GitHub environment named `apple` has these secrets: APPLE_DEVELOPER_ID_P12, APPLE_DEVELOPER_ID_P12_PASSWORD, APPLE_DEVELOPER_ID_IDENTITY, APPLE_NOTARY_KEY_P8, APPLE_NOTARY_KEY_ID, APPLE_NOTARY_ISSUER. Until they are set, the dmg is ad hoc signed and you allow it once in System Settings.

A published Windows installer is Authenticode signed only when the GitHub environment named `windows` has WINDOWS_AUTHENTICODE_PFX_B64 (the certificate as base64) and WINDOWS_AUTHENTICODE_PFX_PASSWORD. After signing, the signature is checked, and the job fails if it does not verify. Until the secrets are set, the installer is unsigned and Windows asks you to choose More info, then Run anyway. The release prints a skip line that names each missing secret. Setting the repo variable WINDOWS_SIGNING to `required` fails a publish that is still unsigned.

The Windows install script still checks SHA256SUMS and does not check SHA256SUMS.sig. Windows PowerShell 5.1 cannot check an Ed25519 signature.

## Updating

Download the new Mac dmg or the Windows installer from the release and replace the app. Then run `vyre space up` on your server.

The Vyre app on the web is now web.vyre.run, and app.vyre.run sends you there. Passkeys made at app.vyre.run do not carry over: sign in with your space address, username and master password, then add a new passkey. A phone may show the old app for about a day until it refreshes; close and reopen it to speed that up.
