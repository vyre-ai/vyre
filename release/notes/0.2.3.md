Vyre 0.2.3 is the Sessions release: a session on your server can carry on where another left off, your phone and Mac pair to the server more safely, and the Mac app can set Vyre up for you. This is a release candidate. It is for testing, not for the stable channel.

## New

- Continue where you left off: a conversation can be picked up from another place without starting over.
- The Lumen Mac app: it sets up Vyre on a Mac that has nothing installed yet, asking for the Mac password in a dialog instead of a terminal. The glass look is checked on the built app.
- Several Claude and other provider accounts on one server, each with its own sign-in and endpoint. A provider's only account is its default. (#20, #42)
- Phone pairing asks before it redeems a link, and the hosted phone app only trusts the relay that served a pairing record.
- Planner, Vault, Agents, Drive and Settings are redone in the new design, with held requests said in plain words ("Spend 150 USD on northwind-ads").
- Git hooks work only for their own repository, so a session's hooks never run in another project.

## Fixed

- The install script ends on the box actually running. If Vyre did not start, it now says so and exits with an error instead of reporting success.
- Installing from a checkout (`--from`) as root now starts the server instead of stopping short.
- An idle Vyre no longer starts a program every minute looking for a graphics card it does not have. The idle processor use on a server without one drops from about 80 milliseconds a minute to about 10. (#71)

## Known issues

- Setting up Vyre from Safari on an iPhone has passed one test run on a simulator and has not been tried on a real phone. Treat it as unproven.
- The browser setup (the passkey step on the setup page) has not been walked on this release. It needs a real passkey and a browser, so it is walked by a person or it waits for a hosted browser run. Do not treat this release as ready for the stable channel until that walk exists.
- The Android app is not part of this release.
- Typed pairing codes need a newer relay than the one running today. They are not in this release.
- A fresh Vyre with no graphics card still shows one short burst of processor use two minutes after it starts, from the update check.

## Updating

A Linux server updates from Settings, or with `vyre update`, once a stable 0.2.3 is out. A release candidate is installed on purpose, by name. Your data, vault and sign-ins stay as they are.
