Vyre 0.3.3-rc.3 is a release candidate on the beta channel, for testing before 0.3.3. It makes one person's own install work without help on a first start, and closes several gaps found in rc.2. Do not put a team on it yet: the work that lets a member's tools act on her own things is not in this candidate.

## What to test

- A fresh install on a server, from the line the Mac app gives you. The installer, `vyre status` and the app should tell you what is happening the whole time Records sets itself up, and every module, including reminders and the agenda, should be running at the end without a restart.
- `vyre uninstall`, then a fresh install on the same server.
- Pairing your phone or computer with the app, and your vault from those devices.
- Approved skills in a session on a server.
- A queued message in a team chat on a server that has tini installed.

## Fixed since 0.3.3-rc.2

What a person sees and changes:

- Reminders and the agenda start by themselves on a first install. In rc.2 they gave up while Records was still setting up and stayed failed until `vyre down` then `vyre up`.
- `vyre status` says "busy setting up" while Records sets itself up, not "vyred not running" or "the record store is not available yet". The installer's last lines say Records is still setting up.
- A reinstall on a server that had Vyre before no longer stumbles on its first start (it used the image recorded by the earlier install).
- A failure while Records finishes setting up on a first start is recorded and retried, instead of stopping the server.
- `vyre uninstall` stops and removes each Space's record store (its database, cache, server and worker). Your records stay or go as you choose with `--keep-data` or `--delete-data`.
- A hand-run `vyre update` keeps the server's protection against going back to an older release, or says it could not.
- `vyre update` with nothing newer does nothing, and a slow first start is no longer rolled back as a failed update.
- Approved skills reach a session that runs sandboxed.
- A message queued in a team chat is answered on a server that has tini installed.

Who can see and change what, as rules:

- The records of chats, file shares and logged communications are read and changed only by the people they involve, and by the owner and admins.
- A device paired with a classic pairing code (`relay.pair.start`, from the command line or the Deck) gets only a cut-down live feed until you mark it as yours (`vyre relay mark`). Devices you pair with the app are marked at pairing.
- Your vault is refused to a device you have not confirmed, even when you are the only person on the server. Your own command line on the server and your confirmed devices always reach it.

## Known issues

rc.3 is for one person's own install. Do not put a team on it: the next candidate is the release for teams.

- A team member's AI in a team chat can use what the Space's assistant has been allowed to use. It can see which services and mail accounts the owner has connected, pause the assistant's computer for everyone, and reach those connected services, including reading connected mail. A send she asks for waits in the owner's approvals, shown as an assistant's request. The vault refuses her. Do not add members to a Space whose assistant has connected accounts or a computer.
- A team member's AI can read, change and delete documents made by anyone in the Space, including the owner's, and can see the Space's settings and its spend totals.
- A team member can see the team-member list and every project record in the Space through Records, and open projects she is not on.
- A team member can see every task through the tasks list, including the owner's own.
- A team member sees in her event log that a file was written, and its path, for files she cannot open.
- On a device that joined a team, Now, Tasks, Projects, Records, Calendar and Tags show her own home's things, not the team's.
- On a team server, the project folders are kept apart by Vyre, not by the file system: a member's session can reach another project's folder.
- Agents and agent teammates answer only the owner and admins. A member's request to one is refused with a next step.
- Inviting someone as an admin: the four words they read you from their card are not checked against your Space's words, so any text passes. Send admin invites only privately.
- On a server with only you on it, a device you paired with a classic pairing code reaches your settings, computers and connected accounts (not your vault). This is by your choice for a one-person server; never share that code.
- `vyre uninstall` does not yet remove Publish or app containers. On a server that had them, run `docker ps -a` and remove the `vyre-pub-*` ones by hand.
- First install with Records: Records takes from several minutes to about half an hour to set itself up, depending on the server. Vyre answers the whole time and says what it is doing.
- Contacts, organizations and team calendar events are shared by design: members can change and delete them, and deleted ones are in the Bin.
- A permission question from the AI that nobody answers holds every later message in that chat, for everyone, until someone answers it.
- A person removed from a chat is cut off from its live activity at the next call anyone makes into that chat, not at the instant of removal.
- `vyre call` typed inside an AI agent's terminal is refused. Agents reach Vyre's tools through the connection Vyre gives them.
- The command is still `vyre capsule`; a `vyre lumen` name comes later.
- Servers on rc.1 or rc.2 are not upgraded by this release. Install it fresh: back up, clear `/srv/vyre` (hidden files too), and on a server that had Vyre remove the old `vyre-*` containers and networks first.

## Updating

This release is on the beta channel only. A server on the stable channel stays on 0.3.1.
