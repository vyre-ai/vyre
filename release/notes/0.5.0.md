Vyre 0.5.0 puts your people and your agents in the same chats, and lets an agent take a task, finish it and say where it is stuck.

## What's new

- Chat with people and agents. @ a teammate or an agent, # a record, a file, a project or a tag. Anyone in a Space can make an agent and share it with a person or a role as Can use or Can edit.
- Agents wake on a task. Give a task to an agent, or let a Flow's agent step do it. The agent wakes once, with the task, the record and the Flow it came from. It finishes the task, hands it on, or marks it stuck with the error in plain words and a next step. A task is never left open in silence.
- One AGENTS.md per agent and per project (CLAUDE.md is kept the same). Type @ or # in the editor to point at a person, a record or a file. Every chat in a project, and every agent session, reads the file in its own folder.
- Flows: "When something happens, do these steps". Start from a person, a schedule, a change to a record, a stage or a watcher. Steps include find, create, update, find or create, wait until a time or a date, ask, assign, send, and hand to an agent. Text inside a step fills in values from the record and the records linked to it, and dates read the way people write them ({now}, {today}). Each Flow has a run page with a step timeline, the approver's name and the details of every step.
- Approvals. A step that sends something out waits for a person's yes. The Ask step offers people and roles only.
- Records: every field shows its template token, by group, with a copy button. Tags work on records, projects and chats, with tag filters and a Tags page. Import an Excel or CSV file on any list. Export a list as CSV from the web app; a cell that would run as a formula in Excel is quoted.
- Documents: fill a Word template from a record and the records linked to it, file it on the record, and send it for signature. A signer needs no account.
- Files: link a Google Drive or Dropbox folder, browse it, open files and write changes back. Each person uses their own account.
- Vault: ten groups, a sidebar to match, and an Add picker by provider that shows each provider's own fields in the order its console does.
- Sites: an agent builds a site, previews it at a private address and puts it live with one yes from you. A domain shows the DNS record to add and checks itself.
- Needs you: one place for everything waiting on a person. A date ask has a date picker, a file ask has a file picker, and a stuck sign-in opens the Vault's Add sheet with the item filled in.
- Settings: dead links fixed, every row says what it does, and an About page.

## The classic pairing code is gone

A device now joins only by signing in with the person's name and approving it on a device already signed in, or with a space code and the same words. The one-time code any holder could redeem (`vyre relay pair`, `vyre phone add`, the long `vyre.run/pair` link, `relay.join`) is removed; asking for one is refused in words that name the next step.

Upgrading: a device that was paired the old way keeps working only if it is already marked as the owner's. Any other is removed on its next connection and its app shows the pair-again screen. To bring it back, pair this device again from your app: Devices, Add a device. To keep a phone of yours, mark it first with `vyre relay mark <id>`, before it next connects.

## Sign in by name

A new device types the person's name and asks to sign in. Every device already signed in to that name is asked "Sign in on [device]? These words should match", the new device shows the same three words, and one Approve adds it. Nobody types a code. A request lasts 2 minutes, and a name can be asked about 3 times a minute. The relay answers the same whether or not the name has a device online. Read the three words off the new device's own screen, never from a message. A stranger can keep a name busy by asking about it over and over; the other ways to add a device still work. This needs the relay Worker deployed with its new Durable Object class SigninSlot.

## Continue with GitHub

The first screen has a Continue with GitHub button. The relay and the escrow Worker are built so that GitHub plus your master password can add a limited device. Before you link GitHub, update every server of yours: a server on older rules cannot verify a device list that holds the relay's key, so its identity checks for that person stop until it is updated. Devices paired in person are unaffected.

## Updating

A Linux server updates from Settings, or with `vyre update`.

## Security notes

- Advisory GHSA-32h6-gq86-772f is fixed in 0.5.0. A call on a device removed from a Space is refused, and a fact the kernel refuses never falls back to a module's service chain.
- A bare mobile label is never a caller. It is out of every list of person surfaces, the daemon refuses a call that carries it, and a paired device arrives as its own device.
- A project's instructions reach a chat's prompt only for people who may use the project, and references in an instructions file fail closed.
- Member reach: a linked Drive or Dropbox folder follows the member's own access, each member keeps to their own link, and the firm's Google or Microsoft 365 key lets a member read only their own mail, calendar and drive.
- Adding or removing accounts and rewriting session history are the person's acts. An agent, a model, a guest or an MCP caller is refused.
- Continue with GitHub: the relay and the escrow Worker share one secret. If the relay were compromised, an attacker could ask the escrow to add a limited device and release the sealed Secret Key for a linked GitHub account, rate-limited. The new device still cannot open the vault without the master password, and it cannot change who speaks for the identity until another device confirms it.
- Unlinking GitHub deletes the stored key and removes the relay's entry. A device that signed in with GitHub just before an unlink can remain as a limited device; remove it in Settings, Account.
- A checkpoint no longer uploads a coding agent's sign-in (Claude's `.credentials.json`, Codex's `auth.json`) to the Space. If a member used a session on an rc.3 server, sign their Claude and MCP accounts out and back in: earlier checkpoints may hold a copy.
- On the web, a member's Secret Key sits in browser storage, readable by the app's own scripts. It opens nothing without the master password.

## Known issues

Every test passes in CI for this release. The full list, with what to do today, is in docs/known-gaps.md.

- A member can read every row of a record type the Space defined itself, even when the row is linked to a project the member is not on. Per-record privacy for custom types is planned for 0.5.1.
- A Viewer's AI can read a project's records and files through Vyre, but cannot open the project's folder directly.
- Renaming a project on a team server changes its short name, which keys the project's folder group. The next session started in the renamed project is refused in words that name the old name.
- A "For each" step handles up to 50 items in the editor, and a longer list is cut without a note on the run page. An agent step has no deadline: a session that ends without finishing is marked stuck, but one that never ends is not timed out.
- A Flow email cannot carry CC, BCC or attachments. Members cannot inspect a Flow over MCP.
- CSV export is in the web app only.
- A member cannot add a setup token or API key as their own AI account. Sessions do not read other items in a member's own vault yet, and the firm Microsoft 365 app is read-only.
- Mac as the server: tested on a clean macOS in CI. The virtual machine for agents' computers, Records and an agent computer starting are not yet proven on real Mac hardware.
- Only Claude is proven live. Codex and Grok work against recorded sessions.
- Nothing has been walked on a real iPhone or Android yet, and native push needs Apple and Google push accounts, which are not set up.

## Changes

- Files have one layout, by ids that a rename never changes. Existing project folders do not move. See docs/reference/files-layout.md.
- Using a Mac as the server is one Terminal line (`curl -fsSL vyre.run/box/install-mac-server.sh | sh`).
- Your servers follow you. After you sign in on a new device and open your vault, Settings, Servers shows "Found on your other devices" with a Connect button.
- Every member has a vault of their own on the Space's server, opened with their own master password and the Secret Key their device holds. The owner, the other members and the server's disk cannot read it.
- A member can keep their own MCP servers (Settings, Connections, MCP, Your accounts).
- The firm can connect a Microsoft 365 app so each member reads their own mail, calendar and OneDrive, read-only.
- A Space can connect its own email sending service (Resend, Mailgun, Postmark, SendGrid or SMTP), and a Flow's Send email step goes out through it. Every send waits for a person's yes. Flows can also text through your own Twilio account.
- The chat composer is one calm box with a + menu and one Answering control. The @ and # menus nest and run from the keyboard. Message actions are an icon row with keys (R reply, C copy, A ask, E edit).
- One set of words in the app: "agent" for what used to say "assistant", "Files" for the Drive, "Playbook" for a project template and "Objects" for record types.
- When your server answers with something Vyre cannot read, the app says "Vyre could not read your server's answer. Try again."
