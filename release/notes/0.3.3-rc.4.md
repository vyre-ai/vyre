Vyre 0.3.3-rc.4 (draft; not released).

## The classic pairing code is gone

A device now joins only by signing in with the person's name and approving it on a device already signed in, or with a space code and the same words. The one-time code any holder could redeem (`vyre relay pair`, `vyre phone add`, the long `vyre.run/pair` link, `relay.join`) is removed; asking for one is refused in words that name the next step.

Upgrading: a device that was paired the old way keeps working only if it is already marked as the owner's. Any other is removed on its next connection and its app shows the pair-again screen. To bring it back: pair this device again from your app: Devices, Add a device. Mark a phone of yours first (`vyre relay mark <id>`, before it next connects) to keep it.

## Sign in by name

A new device types the person's name and asks to sign in; every device already signed in to that name is asked "Sign in on [device]? These words should match", the new device shows the same three words, and one Approve adds it. Nobody types a code. A request lasts 2 minutes; a name can be asked about 3 times a minute. The relay answers the same whether or not the name has a device online, so a name with none looks like a request nobody answered. This needs the relay Worker deployed (new Durable Object class SigninSlot).

## Known issues

- Renaming a project on a team server changes its short name, which keys the project's folder group, so the next session started in the renamed project is refused in words that name the old name. A re-key step comes later.
