Vyre 0.3.3-rc.4 (draft; not released).

## The classic pairing code is gone

A device now joins only by signing in with the person's name and approving it on a device already signed in, or with a space code and the same words. The one-time code any holder could redeem (`vyre relay pair`, `vyre phone add`, the long `vyre.run/pair` link, `relay.join`) is removed; asking for one is refused in words that name the next step.

Upgrading: a device that was paired the old way keeps working only if it is already marked as the owner's. Any other is removed on its next connection and its app shows the pair-again screen. To bring it back: pair this device again from your app: Devices, Add a device. Mark a phone of yours first (`vyre relay mark <id>`, before it next connects) to keep it.

## Sign in by name

A new device types the person's name and asks to sign in; every device already signed in to that name is asked "Sign in on [device]? These words should match", the new device shows the same three words, and one Approve adds it. Nobody types a code. A request lasts 2 minutes; a name can be asked about 3 times a minute. The relay answers the same whether or not the name has a device online, so a name with none looks like a request nobody answered. The person must read the three words off the new device's own screen, never from a message. A stranger can keep a name busy by asking about it over and over (the limits above); the other ways to add a device still work. This needs the relay Worker deployed (new Durable Object class SigninSlot).

## Known issues

- A Viewer's AI can read a project's records and files through Vyre, but not open the project's folder directly.
- Renaming a project on a team server changes its short name, which keys the project's folder group, so the next session started in the renamed project is refused in words that name the old name. A re-key step comes later.
- Vyre server on a Mac: tested on a clean macOS in CI; the virtual machine for agents' computers (Colima), Records (Twenty) and an agent computer starting are not yet proven on a real Mac. A hosted runner cannot run a virtual machine, so a proof on real Mac hardware is scheduled separately.

## Changes

- Files have one layout. `lib/files/layout.js` says where a project, an agent (instructions, context, memory, work), a record's attachments, a template, a flow and the Space's own documents live, by ids that a rename never changes. Existing project folders do not move. See docs/reference/files-layout.md.
- Using a Mac as the server is one Terminal line (`curl -fsSL vyre.run/box/install-mac-server.sh | sh`). It checks git, installs Vyre's own pinned Node, Colima, Lima, Docker command, gh and Headscale (it never uses Homebrew's copies and never touches yours), sets the Mac to stay awake and start after a power cut, adds the `vyre` command to your shell, and ends on `vyre space up` for the space code. `--uninstall` removes it all.
- Your servers follow you. When you sign in on a new device and open your vault, Settings, Servers shows "Found on your other devices" with each server your other devices use and a Connect button, no code typed. Pairing a server, joining a team or leaving one updates that list by itself, with no extra yes. (The server side that lets a new device in is still landing, so Connect may say a server does not admit this device yet.)
- Flows now read as "When something happens, do these steps". The list is in groups and says in one sentence what each Flow does. New flow lets you pick what starts it, then add steps: make a record, start a project from a template, hand work to an agent with your instructions, assign a task, send an email, wait for someone's yes. Assigning to a team group shows as coming.
- Each agent has one page for everything about it: its instructions (AGENTS.md and CLAUDE.md, edited in place), the files and folders it keeps as context, the models it runs on in the order they are tried, and where it is used (chats, flows, and the Vault items you put at its disposal). Open it from Assistants, on the agent's row.
- Anyone can make an agent. Share it with people or a role as Can use or Can edit, from the agent's page. A folder you link must be one you can read yourself.
