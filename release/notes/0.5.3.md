Vyre 0.5.3 is the same first run on the web, the Mac app and the Windows app, and it retires the install that ran only on one computer.

## What's new

- First run is the same on the web, the Mac app and the Windows app: create your identity, then join a space or create one with one install line (the line carries a one-time code; the server adopts you without comparing four words), then you are ready. There is no choice to run only on this computer. An install that still says it ran only on this computer opens that same first run.
- One identity can own more than one server. Each server adopts you from its own install line.
- Master password and space vault: one username, a master password that unlocks your personal vault, a recovery key, and a space vault key that rotates when someone leaves.
- Chat shows which capabilities are on for a thread, on every surface, through the design library.
- The Windows app asks with the same summary the Mac app shows, including a yes that names the card. It tries Windows Hello, then the TPM. If Hello cannot make the key, the app asks before it uses a software key. A Hello prompt on each signature has not been shown on a real PC yet, so that key is still held and the app asks in its own window first.
- An assistant can ask to enrol a Windows computer or to change how this computer runs. A change to people, devices or vault access waits for your one tap. The card that adds a device names that device, its type, its key fingerprint, and who asked. Nothing changes until you approve. An assistant never receives a vault value, including after you approve. Using the app yourself does not wait for that tap.

## Signing

A published Mac app is Developer ID signed and notarized only when the GitHub environment named `apple` has these secrets: APPLE_DEVELOPER_ID_P12, APPLE_DEVELOPER_ID_P12_PASSWORD, APPLE_DEVELOPER_ID_IDENTITY, APPLE_NOTARY_KEY_P8, APPLE_NOTARY_KEY_ID, APPLE_NOTARY_ISSUER. Until they are set, the dmg is ad hoc signed and you allow it once in System Settings.

A published Windows installer is Authenticode signed only when the GitHub environment named `windows` has WINDOWS_AUTHENTICODE_PFX_B64 (the certificate as base64) and WINDOWS_AUTHENTICODE_PFX_PASSWORD. After signing, the signature is checked, and the job fails if it does not verify. Until the secrets are set, the installer is unsigned and Windows asks you to choose More info, then Run anyway. The release prints a skip line that names each missing secret. Setting the repo variable WINDOWS_SIGNING to `required` fails a publish that is still unsigned.

The Windows install script still checks SHA256SUMS and does not check SHA256SUMS.sig. Windows PowerShell 5.1 cannot check an Ed25519 signature.

## Updating

Download the new Mac dmg or the Windows installer from the release and replace the app. Then run `vyre space up` on your server.
