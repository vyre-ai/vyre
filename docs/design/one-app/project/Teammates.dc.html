Agents place · teammates (ADR 0031)

A teammate is one role in one project: an inbox that runs in order, notes it keeps, and an integrator that owns main.

Any session, person or teammate in the project asks design, and design takes the work one request at a time. Code teammates work on their own branch; the integrator merges them when the tests pass, so you never approve a merge. Only a person creates, shares or changes a teammate.

How it works
1Grouped by project, teammates first, then agents. A row is the role as its name, its state, the running request's first line, the queue and the last result. A shared teammate shows under each project it serves, tagged "shared from Harlow Legal" or "assistant".
2One status model. Violet means waiting on you and nothing else.
workingwaitingfailedidleasleeppaused
3Slots count where the work comes from. Waiting for a slot runs oldest first; Run now beats the project limit once, never the box ceiling. Urgent reorders an inbox, never the slot queue.
4Tabs: Now (live, Stop), Inbox (reorder, cancel, make urgent; each row names its project), Results, Notes (General plus one section per project; Northwind's page shows General and Northwind only), Setup.
5Every pane ends in a summon box. @design does the same from Chat, the Capsule and the phone; the project comes from where you are.

6The integrator comes with the first code teammate. It merges one branch at a time, runs the tests and fast-forwards main; it never forces, and you never approve a merge. A dirty checkout of main parks it ("Waiting for a clean main"). Pushing is off by default.
7One role per project: sharing design into Harlow site is refused in place, with the rename field ready.
8Smooth: Ask lands in the inbox at once through the outbox (Undo 4 s) and takes its real place when the box confirms. Run now, Cancel and inbox reorders are optimistic. Notes save in place ("Saved 14:02"), and the list paints from cache in under 1 s.
