How it works
1All five kinds fit the one-row rule: a title, one detail line, then kind · agent · project. The only addition is "asked by Q3 report" under a teammate's ask, so you see who acts and who started it.
2New teammate: kit proposes and never creates. The detail shows the drafted role, tools and grants with Approve, Edit and Not now. Approve is the one primary.
New teammateNorthwind Bakery
kit suggests a teammate: intake for Northwind Bakery Tools: files, web · folder · no grants
3Merge failed: the branch, the failing tests or the conflict, and three actions. Ask design to fix (F) queues an urgent request; Discard the branch is a hold with its count. main never moved, so nothing needs undoing.
4Stuck: a request that failed twice, in the teammate's own words ("design is stuck: needs the brand colours file"). Retry, Cancel or open its session.
5Usage pause: one row per plan window, never one per teammate. Running requests finish; new ones wait until 16:00 or until Resume anyway, which lasts to the next window.
6No red. A failed test is neutral text with the crossed glyph, and violet stays on the dot and the label.
7Smooth: Approve collapses the row on commit and leaves a 4 s Undo in its place (drawn on the phone), sent through the outbox. The terminal output is cached with the row, so the detail opens without a spinner.
