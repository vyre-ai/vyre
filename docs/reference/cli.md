# CLI reference

> Generated by `scripts/gen-docs-reference` from the command files in `core/cli/commands/`. Do not edit this page: edit the code, then run `npm run docs:ref`.

`vyre` is a thin client: every command is a call to vyred, so the terminal, the Deck and the Capsule never disagree about what is true. With no arguments, `vyre` runs `vyre home` (your projects, a new session and your agents).

### vyre up

Start vyred and print the onboarding link, or this box's address.

```
vyre up [--box|--connect <addr>] [--json] [--no-capsule]
```

### vyre down

Stop it.

```
vyre down
```

### vyre box

Put Vyre on a server from this Mac, and look after it.

```
vyre box [add|update|backup|move|remove]
```

### vyre status

Is it running, and what is it running.

```
vyre status
```

### vyre projects

Every project.

```
vyre projects
```

### vyre recall

Search every session for what was said (vyre recall eval <file> to measure it).

```
vyre recall <query>
```

### vyre index

Index new and changed sessions now.

```
vyre index
```

### vyre new

Make a project by picking sessions (flags: --home --thread --workspace --person --org --no-pick).

```
vyre new [name]
```

### vyre open

A project: what its threads are told, and its threads.

```
vyre open <project>
```

### vyre threads

Headless threads vyred runs: start, send, list, watch, lease, release, asks, answer, stop (anything else searches sessions).

```
vyre threads start|send|watch|answer|stop …
```

### vyre threads

Every session on this machine, searched by what was said (--project, --all).

```
vyre threads [search]
```

### vyre resume

Open a thread in Claude Code where it ran, with its project's brief (--project, --name).

```
vyre resume <thread>
```

### vyre start

A new thread in this folder's project, with its brief (--project).

```
vyre start [name]
```

### vyre context

What a new thread in a project is told.

```
vyre context [project]
```

### vyre pick

Put threads into a project by hand.

```
vyre pick <project> <thread>...
```

### vyre unpick

Take picked threads out of a project.

```
vyre unpick <project> <thread>...
```

### vyre agents

Agents: list, create, update, ask, threads, usage, stop, delete.

```
vyre agents [create|update|ask|threads|usage|stop|delete] …
```

### vyre capsule

The Mac command bar: Control twice, anywhere.

```
vyre capsule [--dev] | build [--app] | install
```

### vyre memory

What memory holds, or everything about one thing.

```
vyre memory [about] [--project <slug>] · correct|corrections|uncorrect|merge|split|pin|mute
```

### vyre name

This box's address: <you>.vyre.run.

```
vyre name [check <n>|claim <n>|ts.net|release]
```

### vyre why

The turns a fact came from.

```

```

### vyre learn

The lessons Vyre learned from you, and what it proposed.

```
vyre learn [show|add|accept|retire|level|scope|relax|stats|signals|skills]
```

Also: `vyre lessons`.


## Not listed by vyre help

These work, but `vyre help` leaves them out: they are for the box's service manager, for setup and recovery, or what `vyre` runs with no arguments.

| Command | What it does |
| --- | --- |
| [`vyre owner`](#vyre-owner) | the one Tailscale login this box serves |
| [`vyre home`](#vyre-home) | your projects, a new session, and your agents |
| [`vyre restore`](#vyre-restore) | put a backup back (vyred must be stopped) |
| [`vyre uninstall`](#vyre-uninstall) | remove the systemd units (the data stays unless --purge) |
| [`vyre daemon`](#vyre-daemon) | run vyred in the foreground (what systemd runs) |

### vyre owner

The one Tailscale login this box serves.

```
vyre owner <tailscale login>
```

### vyre home

Your projects, a new session, and your agents.

```
vyre home
```

### vyre restore

Put a backup back (vyred must be stopped).

```
vyre restore <file> [--force]
```

### vyre uninstall

Remove the systemd units (the data stays unless --purge).

```
vyre uninstall --system [--purge] [--dry-run]
```

### vyre daemon

Run vyred in the foreground (what systemd runs).

```
vyre daemon
```
