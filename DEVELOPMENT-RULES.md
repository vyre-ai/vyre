# Development rules

Every rule that decides how code is written in this repository, in one file. It is for human developers and for AI agents alike. Each rule has the rule in one line, why it exists, and how it is enforced: the guard test or CI check that fails when it is broken, or "review only" when a person has to catch it.

A rule marked with a guard cannot be argued with: fix the cause, never loosen the guard. Many guards hold a list that may only shrink (a ratchet). A list that grows needs `[ratchet +N: why]` in a commit message and a reviewer's yes (preflight rule R1). If a rule here and the code disagree, one of them is a bug; open an issue.

Where a rule comes from: the spec principles ([Section 2](docs/architecture/spec.md#2-principles)), the engineering rules ([Section 14](docs/architecture/spec.md#14-engineering-rules)), the security floor ([Section 11](docs/architecture/spec.md#11-the-security-floor)), the decision records in `docs/adr/`, the guard tests in `test/` and `scripts/team/preflight.mjs`, and the owner's standing rulings.

Contents: [Architecture](#architecture), [Security](#security), [UI and design](#ui-and-design), [Data and records](#data-and-records), [Flows](#flows), [Agents and prompts](#agents-and-prompts), [Writing](#writing), [Tests and CI](#tests-and-ci), [Releases](#releases), [Git and commits](#git-and-commits).

## Architecture

1. **Everything goes through the kernel.** A part acts on people, records, secrets and models only through the kernel's contracts (`kernel/contracts`), never around them. Why: one place decides who may do what. Enforced: `kernel/contracts/contracts.test.js`, `kernel/size.test.js`, `test/boundaries.test.js`.
2. **Parts talk through the registry and events, never by importing each other's files.** The kernel (`core/config`, store, events, modules, presence, daemon) and `lib/<name>` may be imported by anyone; a lib may import only the kernel and other libs. Why: a module can be removed or replaced without a ripple. Enforced: `test/boundaries.test.js`.
3. **Everything is a module, with no special cases.** Core services, the harness pieces, surfaces and third-party additions use one module contract (`module.json` and an entry file). Why: one loader, one set of checks. Enforced: `test/module-sdk.test.js`, `test/module-sdk-conform.test.js`, `test/module-api-compat.test.js`, `test/modules-boot.test.js`.
4. **One tool is defined once** and becomes the MCP tool, the HTTP route and the CLI command from that definition. Anything the app can do, `vyre` can do. Why: no surface drifts from another. Enforced: `test/mcp-server-tools.test.js`, `test/app-tool-names.test.js` (every tool name a screen sends exists).
5. **A module emits only the events its manifest declares** under `watches.emits`. Why: the loader refuses an undeclared event at run time, which only fails when the line runs. Enforced: `test/events-declared.test.js` (its `KNOWN` list only shrinks).
6. **A tool declares every input it reads.** Why: the registry refuses undeclared keys from a caller that is not a module, so an undeclared input works in a unit test and fails over the wire. Enforced: `test/declared-inputs.test.js`. No tool declares an input named `approval`, which is the envelope key a held act's retry carries: `test/approval-reserved.test.js`.
7. **A tool that takes a project or a folder declares it** (`projectArg`, `cwdArg`) so the registry checks the agent's grant once. Why: an undeclared one is silently uncovered. Enforced: `test/project-arg.test.js`.
8. **A read is a read.** A tool that declares `effect: "read"` writes nothing, emits nothing and calls no write tool. A tool that must write declares `effect: "write"` and says who may call it. Why: a read that writes (a lazy migration, a seen marker) surprises every caller. Enforced: `test/reads-are-reads.test.js` (its `KNOWN_WRITERS` only shrinks).
9. **A raw route says whether it only reads or which methods write**, and answers only those. Why: any page the person opens can make a GET, so a route with a side effect must never answer GET. Enforced: `test/route-declared.test.js`.
10. **A module relaying a call never invents who it acts for.** The registry sets the call's origin; work started later keeps `ctx.origin()` and replays it with `ctx.withOrigin`. Why: a relay must not turn a model's call into the box's own. Enforced: `test/module-origin.test.js`.
11. **A module's migration list is append-only.** Never move, edit or remove a released step; add at the end. Why: an upgraded box has already run the earlier ones. Enforced: `test/migrations-append-only.test.js` (released hashes in `test/migrations.released.json`).
12. **One mechanism per job; before adding a mechanism, build on the existing one.** Role list, secret detector, grant model, approval path, id minting, scrubbing, cron parsing, address rules, WebSocket framing, base32 and canonical JSON each exist once. Why: two answers to one question are the commonest source of a security bug. Enforced by the single-owner guards: `test/one-mechanism.test.js`, `test/one-role-list.test.js`, `test/one-person-surfaces.test.js`, `test/one-identity.test.js`, `test/one-registry.test.js`, `test/ids-single.test.js` (ids come from `lib/id.js`), `test/scrub-single.test.js` (secret scrubbing is `lib/scrub.js`), `test/http-single.test.js` (every outward request goes through `lib/http.js`), `test/netguard-single.test.js` (`lib/netguard.js`), `test/cron-single.test.js` (`lib/cron.js`), `test/ws-single.test.js` (`lib/ws.js`), `test/bytes-single.test.js` (`lib/bytes.js`, `kernel/core/canonical.js`), `test/credential-shapes-single.test.js` (`lib/credential-shapes.js`). New code that adds a second way fails review: **review only** for anything those guards do not name.
13. **A surface never keeps its own copy of a list another module owns** (tool names, role ids, AI providers, model names, tool-policy sets). It reads the owner and follows its change event. Why: a copy drifts the day the owner changes. Enforced: `test/a5-no-copies.test.js`, `test/cohesion-drift.test.js` (both lists only shrink). Copies that cannot import `lib/` are generated by `scripts/sync-copies.mjs` and held by `test/generated-copies.test.js`; never hand-edit one.
14. **Business data is a record type.** A module's own database is for private operational state only (tokens, caches, per-computer rows, queues, rebuildable indexes). Why: a record type is shared, permissioned and visible; a private table is none of those. Enforced: `test/private-stores.test.js` (a module that opens SQLite must say why its data is operational).
15. **A source file over 2,000 lines does not grow.** Add a new focused file instead. Why: files that size stop being reviewed. Enforced: `test/file-size.test.js` (list in `test/file-size.json`). Kernel growth needs `[kernel +N: why]` after the lead's ruling (preflight K1), and the trusted base is capped (`kernel/size.test.js`).
16. **A new dependency needs one line saying why no existing one serves**, in `ALLOWED-NEW.md`, and the changelog says why it is worth having. Why: boring, readable code with almost no dependencies. Enforced: `test/dependency-guard.test.js` (reasons in `test/allowed-dependencies.json`).
17. **Boring, readable code.** Node 22.5 or newer, ES modules, plain JavaScript with JSDoc types and `// @ts-check`, SQLite through `node:sqlite`, no build step for the core, tests with `node:test`. Why: anyone can read it and nothing hides in a toolchain. Enforced: `test/dependency-guard.test.js` for the dependency side; the rest **review only**.
18. **A promise raced against a clock goes through `lib/within.js`.** Why: a hand-rolled race with an unref'd timer let the event loop drain with the call still pending. Enforced: `test/within-hygiene.test.js`.
19. **A child process's stdin gets an error listener** before anything is written or ended. Why: an unhandled EPIPE takes vyred down and try/catch does not see it. Enforced: `test/stdin-hygiene.test.js`.
20. **Light by default.** vyred idle stays under 0.5 percent of one core and 150 MB resident, with no timer faster than once a minute; heavy work runs at low priority. Why: Vyre runs all day on the person's machines. Enforced: `npm run perf-check` (`scripts/perf-check`) in CI, `test/bundle-size.test.js` for the web bundle.
21. **Use only public Claude Code surfaces** (plugin system and documented CLI flags). Transcript reading lives in the one adapter, `core/transcripts`, and degrades to "no history". Why: nothing breaks when an undocumented thing changes. **Review only.**
22. **Settings the person can change have a reader.** A key declared in `module.json` that nothing reads is removed or wired. Why: a toggle that does nothing is a lie. Enforced: `test/settings-have-readers.test.js` (its `DEAD` list only shrinks).
23. **A security or behaviour switch read from the environment goes through `devSwitch()`** (`kernel/devbuild.js`), so a release build ignores it. The loopback seam in `lib/http.js` is for test files only. Why: a release must not be steerable by an environment variable. Enforced: preflight rule S1, `test/http-seam.test.js`.
24. **Decisions get a record.** Anything a future contributor would ask about (a trade-off, a boundary, a thing you chose not to do) is an ADR in `docs/adr/`, numbered next, listed in `docs/nav.json`. Why: the reason outlives the author. Enforced: `scripts/docs-check` for the nav; otherwise **review only**.

## Security

1. **Fail closed.** When who is calling, the chain or a definition cannot be read, the answer is a refusal, never a fallback to a broader reading. Why: the 0.5 advisory GHSA-32h6-gq86-772f was a fallback. Enforced: `test/peer-race.test.js` and the golden tests in `kernel/golden/`; the principle itself is **review only**.
2. **Nothing goes out as the person until the person has seen the final words, and the Gate holds every outward send.** Every outward tool says so in its `module.json` (`outward: true` or a Gate kind). Unclear means outward. Why: the outward moment reads that flag and nothing else. Enforced: `test/outward-flags.test.js` (the exceptions list carries a reason each), `test/presence-bypass.test.js`, `test/one-yes-floor.test.js`.
3. **A person's yes for outward actions is the person's own.** A model, agent, hook or guest never approves its own held act, and "mcp" and "harness" in any form are model callers, never the person. One answer in one place: `lib/caller.js` (`isPerson`, `modelKey`). Why: an unnamed `mcp` once became the person in chrome, hands and memory. Enforced: `test/model-is-never-person.test.js` (its `FROZEN` list only shrinks), `test/person-only-guard.test.js`, `test/stage-gate-model-paths.test.js`, `test/thread-label-hygiene.test.js`, `test/person-label-hygiene.test.js`.
4. **Who did something comes from the kernel's chain, never from the call's input.** A tool input that names a person (`created_by`, `owner`, `as`, `approver`) is a target or a lookup and is reviewed. Why: a forged field would be a forged identity. Enforced: `test/identity-from-input.test.js`.
5. **Reach is written down, never defaulted.** Every tool states `reach`; "anyone" needs a reason that names a guard; a person-only tool says so in the registry as well as in presence. Why: a forgotten line is an open door. Enforced: `test/reach-explicit.test.js`, `test/reach-registry.test.js`, `test/reach-anyone.test.js`, `test/reach-anyone-behaviour.test.js`, `test/reach-person-only.test.js`, `test/reach-person-split.test.js`, `test/reach-classes.test.js`, `test/agent-reach-classes.test.js`, `kernel/retrofit/agent-reach.test.js`.
6. **A plain model session can reach no write or outward tool** unless it is refused, held for the person, or on the short reasoned list. Why: the model's shell can claim any caller label. Enforced: `test/plain-session-writes.test.js` (list in `test/plain-session-writes.json`).
7. **Sealed fields and vault values never reach a model, an agent, a log or an event.** A value is revealed only to a person who has just proved presence on their own device, for that one value. Why: security floor item 8. Enforced: `kernel/seal/` tests, `test/vault-model-item.test.js`, `test/vault-thread-gate.test.js`, `test/vault-member-gate.test.js`, `test/relay-never-reads.test.js`.
8. **A definition holds a reference to a credential, never the key.** Flows, kits, skills, drafts and configs name `vault://item` or a Connection. Why: a stored definition is copied, shared and read by models. Enforced: `test/references-not-values.test.js`.
9. **What a vendor credential looks like is written once** (`lib/credential-shapes.js`); a new vendor key is one row there. Why: two detectors disagree. Enforced: `test/credential-shapes-single.test.js`, `test/credential-pins.test.js`.
10. **A module someone adds can never pair, admit or drop a device, or set the server up.** Why: those change who can reach the server. Enforced: `test/added-module-never.test.js`, `test/names-reach.test.js`.
11. **Adding or removing accounts, and rewriting session history, are the person's acts** (reach person and PERSON_ONLY). Why: ruling of 13 Oct 2026. Enforced: `core/modules/account-tools-person-only.test.js`.
12. **Security code is read by trust before it lands**, and a branch that changes it carries `[reviewed: trust]` (or `[reviewed: lead]`). Why: that code is the floor. Enforced: preflight rule R2.
13. **The relay never reads a client's content**, and the product carries no third-party CDN, font host or analytics host. Why: Vyre keeps nothing about people on its own servers. Enforced: `test/relay-never-reads.test.js`, `test/no-cdn.test.js`, preflight rule S2 (`scripts/team/cdn-hosts.mjs`).
14. **A folder someone else can write to never runs its own commands through vyred's git.** Why: a planted hook or filter driver would run. Enforced: `test/safe-git.test.js`.
15. **A vyred on a temp home never looks for or pairs with a real box.** Why: a stress run once paired with a live box. Enforced: `test/link-guard.test.js`.
16. **Every refusal says what to do next.** A literal refusal message names a real tool, says who decides, or gives an instruction; bad_input is exempt. Every error code a person can meet has a catalogue entry (`lib/error-catalogue.js`). Why: a caller must never be left to guess. Enforced: `test/errors-teach.test.js`, `test/error-catalogue.test.js` (baseline only shrinks).
17. **No other VPN product appears in Vyre.** The built-in network is Wink. Why: owner ruling of 4 Oct 2026. Enforced: the VPN guard in `test/` (its file name and ratchet list carry the other product's word, which this file may not); the ratchet only shrinks.

## UI and design

1. **Design always comes from the component library, `@vyre/ui` (`apps/app/ui`).** Screens import components from `@vyre/ui` and from no other UI library. Why: one look. Enforced: `apps/app/scripts/check-ui-imports.mjs` (`npm run lint:ui` in `apps/app`), which bans `@radix-ui`, `lucide-react`, `nativewind` and the other UI libraries outside `ui/`.
2. **If a component must change, the library component changes. Never make a one-off copy in a screen.** Why: a copy forks the look and the next fix misses it. Enforced: `test/design-rules.test.js` (its `second-primitive` rule fails an import of a second Button, Card, Row, IconButton, Banner, Icon, Avatar, List or Tag; baseline `apps/app/scripts/design-rules.baseline.json`, which only shrinks).
3. **If no component covers a need, draw up a new component, add it to `@vyre/ui`, and use it from there.** Why: the library grows from real needs and stays the one place. **Review only.** The design checker counts hand-built layouts (`StyleSheet.create`) so a bypass shows up: `test/design-rules.test.js`.
4. **Colours, type and layout come from tokens.** No colour literal, no `fontSize`, `fontFamily`, `fontWeight`, `lineHeight` or `letterSpacing` set by hand in a screen. Why: a space's look, the paper scheme and a person's contrast choice reach every screen only this way. Enforced: `test/design-rules.test.js` (`raw-colour`, `type-literal`), `apps/app/src/theme/raw-colours.test.js`, `test/theme-defaults.test.js`, `test/tokens.test.js`.
5. **The retired lime accent does not come back.** Why: owner choice of 30 Sep 2026 (Bone). Enforced: `test/no-lime.test.js`.
6. **Vyre's own screens are drawn from blocks.** A new route under `apps/app/app/u` reaches `BlockScreen` or is named as hand-written, with a reason. Why: a screen is never added without a decision. Enforced: `test/key-screens.test.js`.
7. **A screen never asks a person for a terminal.** No `vyre ...` command inside a string a person may read; use a button. Why: people are not meant to open a shell. Enforced: `test/design-rules.test.js` (`command-line`).
8. **Screens show time through `lib/time`, in a zone the caller names** (the viewer's clock, the space's too). Never format a date or time by hand in a screen. Why: times follow the person's zone and the space's. Enforced: `apps/app/src/time/show.test.js` pins the helpers; a hand-rolled format is **review only**.
9. **No internal word reaches a person.** Strings a person reads never say "vyred", "switchboard", "no such tool", "Deck" or "as Claude Code does"; they say "Vyre", "the box", "the Vyre app". A literal that must carry one ends its line with `// internal-word: <why>`. Why: the product speaks plainly. Enforced: `test/no-internal-words.test.js`, `test/site-words.test.js`, `test/no-deck.test.js`.
10. **Nothing the product ships loads from the network's public CDNs or fonts**; fonts and libraries are vendored, pinned and hashed. Why: no third party sees who uses Vyre. Enforced: `test/no-cdn.test.js`, preflight rule S2.
11. **Web bundle budget.** The first load stays under the ceiling and may not grow more than 10 percent against the recorded baseline. Why: a heavy first load is a slow product. Enforced: `test/bundle-size.test.js` (`.github/scripts/bundle-size.mjs`).

## Data and records

1. **A record type has one keeper.** The gateway enforces which module keeps a type and who may write a project, a seat or a task, in one rule (`kernel/gateway/ownership.js`). Why: one owner per fact. Enforced: `kernel/gateway/ownership.test.js`.
2. **A person's data is never hard-wired to one industry.** Nothing in code, schema, defaults or copy is specific to a trade (law, bakery, studio); templates and kits carry the specifics, and the core stays neutral. Why: Vyre is one product for any team. **Review only** (the hygiene guard keeps real businesses out of shipped code: `test/hygiene.test.js`).
3. **Records are permissioned at the kernel**, and a protected type is read through no route a member could use to reach another person's. Why: privacy is structural. Enforced: `kernel/gateway/*.test.js` (for example `aggregate-visibility.test.js`, `attr-filter.test.js`).
4. **Forget means forget.** Why: a deletion must remove the data, not hide it. Enforced: `test/records-forget.test.js`.
5. **What is left behind reads as words.** No record, task or logged event holds "[object Object]" or the text "undefined" where a value belongs. Why: a task once carried `flow: "[object Object]"`. Enforced: `test/flows-data-hygiene.test.js`.
6. **Ids come from `lib/id.js`.** Secrets, tickets, nonces and passwords are not ids and stay random with no time in them. Why: ids sort by time; secrets must not. Enforced: `test/ids-single.test.js`.
7. **One identity per person**, set once by the spaces module (`spaces.identity.id`); pairing and install read it and never derive their own. Why: two ids for one person split their data. Enforced: `test/one-identity.test.js`, `test/identity-one.test.js`, `test/one-registry.test.js`.

## Flows

1. **A tool a Flow may run (`flow.steps` in `module.json`) gates itself on the person's chain**, and has a line in `test/flow-step-guards.json` naming the guard it relies on. Why: the Flows runner does not ask the kernel's action table, and a read tool has no other gate. Enforced: `test/flow-step-guards.test.js` (a stale line fails too).
2. **A change the Flows host itself published is not published again.** Why: a task change that re-enters the bus loops forever and stop() never returned. Enforced: `test/flows-publish-once.test.js`.
3. **A Flow names credentials by reference, never by value.** See Security rule 8. Enforced: `test/references-not-values.test.js`.
4. **A watcher and a Flow with the same schedule fire at the same moment**, so cron is parsed in `lib/cron.js` only. Enforced: `test/cron-single.test.js`.
5. **A stage gate whose task a person must do is never skipped by a model**, by any path. Enforced: `test/stage-gate-model-paths.test.js`.

## Agents and prompts

1. **One instructions file per agent and per project: `AGENTS.md`.** A session starts in its project's folder and reads it natively; there is no second instructions file. Why: one place to read and edit what an agent is told. Template: `vyre module new` scaffolds one. **Review only.**
2. **The person's assistant does what its person can, except where there is a written reason.** The classification of tools into open and person-only is in `core/modules/agent-reach.js`, and no tool sits in two lists. Why: an assistant is the person's hands, not a stranger. Enforced: `test/agent-reach-classes.test.js`, `kernel/retrofit/agent-reach.test.js`.
3. **A tool description an agent sees stays near 25 words.** Long ones are baselined and only shrink; a new tool is held to the cap. Why: every listed tool costs every session's tokens. Enforced: `test/description-lint.test.js` (baseline `test/description-baseline.json`).
4. **The tools a session is always offered stay within about 30 tools and 6,000 tokens.** Every other tool is reached through `tools_find` and `tools_call`. Why: the budget protects every prompt. Enforced: `test/tools-budget.test.js`, `test/tools-find-quality.test.js`.
5. **Tool names follow one grammar** and the rename table stays sound. Why: names are an interface for models. Enforced: `test/tool-names.test.js`, `test/tool-names-gates.test.js`, `test/tools-text-names.test.js`.
6. **The agent docs (`docs/agents`) are short, true and written for agents.** Each page carries a token budget and a `when`; they are never offered to a person or published; generated blocks match the code. Why: an agent pays for every token it reads. Enforced: `test/agent-docs.test.js` (regenerate with `scripts/gen-agent-docs.mjs`).
7. **A woken or lent agent acts only inside the reach of the person it acts for.** Why: an agent is never the person. Enforced: `test/one-yes-floor.test.js`, `test/agent-change-daemon.test.js`, the `test/reach-*.test.js` set.
8. **A model call goes through the one inference door** (`model.call`, `kernel/contracts/model.d.ts`) and a surface names models through `sessions.models`, never a literal. Why: one place for spend, labels and policy. Enforced: `test/cohesion-drift.test.js`.

## Writing

1. **Never an em dash, never the section-sign character.** Use a colon, a comma or two sentences; write "Section 5.1". Why: owner rule. Enforced for the published docs and the files they include by `scripts/docs-check` (the `characters` check, `scripts/lib/docs/check.js`, run by `test/docs-check.test.js`); in code, commit messages and this file it is **review only**.
2. **No personal branding, no real names, no real businesses, no secrets** in code, docs, tests, fixtures or commits. Examples use the sample world: the user alex, Juniper Studio, Northwind Bakery, the agents juno and kit, and `example.com`. Why: Vyre is a product, not anyone's portfolio. Enforced: `test/hygiene.test.js`, `scripts/lib/hygiene.js` (shared with `scripts/docs-check`, which also bans emails and IP addresses outside the example and documentation ranges).
3. **Product words are industry-neutral and plain.** Second person, short paragraphs, concrete commands in fenced blocks; no marketing adjectives, no "simply", no "seamless". Why: the reader is any team. Enforced: **review only**, with the sample-world and word checks above.
4. **Spaces are Personal, My Cloud and Cloud, never "Basic" or "Pro"** in anything people read; private chats are encrypted to the people in them; times follow the person's zone and the space's; replies are quoted in the same timeline. Why: the 0.2.9 docs rulings. Enforced: `test/docs-rulings.test.js`.
5. **Every feature merges with its doc page.** A feature is not done until the page that describes it is true, in the same change. The page has front matter, is in `docs/nav.json`, and every link and anchor resolves. Why: undocumented features do not exist for users. Enforced: `scripts/docs-check` (`npm run docs:check`), `test/docs-check.test.js`, `test/docs-build.test.js`.
6. **Docs name only commands, tools, config keys and variables that exist.** Why: a stale hint is worse than none. Enforced: `test/docs-index.test.js` (the terms index, `scripts/lib/docs/terms.js`), the `stale` check in docs-check.
7. **Generated pages are never edited by hand.** The reference (`docs/reference`), the architecture map tables and the agent-doc blocks come from `npm run docs:ref`, `scripts/gen-architecture-map.mjs` and `scripts/gen-agent-docs.mjs`. Why: hand edits are overwritten and drift. Enforced: `test/architecture-map.test.js`, `test/agent-docs.test.js`, preflight rule G1.
8. **The architecture map stays a 30-minute read** and names every top-level folder, kernel folder and module. Enforced: `test/architecture-map.test.js`.
9. **Docs that people read never mention the Deck.** Say "the Vyre app". History, ADRs and release notes are exempt. Enforced: `test/no-deck.test.js`.
10. **Copy in code is plain**; the same word list applies to the app, the site and `llms.txt`. Enforced: `test/no-internal-words.test.js`, `test/site-words.test.js`, `test/installer-copy.test.js`.

## Tests and CI

1. **A bug fix comes with the test that would have caught it, and the test must fail without the change.** A behaviour-free change says `[refactor]` in a commit message. Why: a test that never failed proves nothing. Enforced: preflight rule T5 (red first).
2. **Tests beside the code**, `node --test`; cross-module tests in `test/`. Every test gets a temp `VYRE_HOME` through `tempHome` and creates folders only under `SCRATCH` (`test/scratch.mjs`). Why: tests never touch a real `~/.vyre`, real transcripts or the screen. Enforced: `test/tmp-guard.test.js` (the `pretest` and `posttest` leak guard `test/tmp-guard.mjs`), `test/temp-home-claude.test.js`.
3. **Every test file imports the Mac guard** (`scripts/mac-test-guard.mjs`), so a test never runs on a person's Mac. Why: a test once reached a live machine. Enforced: `test/mac-test-guard.test.js`, `scripts/check-test-guard.mjs`.
4. **Every test file is run by the runner.** A file outside every glob in `scripts/test-counts.mjs` is a green that never saw it; a file that must run elsewhere is named in `EXTERNAL` with the workflow that runs it. Enforced: `test/every-test-runs.test.js`.
5. **A test file runs every test it recorded.** Fewer tests than declared or than the last recorded run fails (`test/test-counts.json`, `scripts/test-counts.mjs`). Why: a crash that skips the rest looks green. Enforced: `test/test-counts.test.js`, the runner itself.
6. **No skips, no todos.** A new `test.skip`, `test.todo`, `it.skip` or `skip: true` is refused. The one exception is a test of a platform's own behaviour, which runs on that platform's CI. Tests that may not skip where the job has what they need are listed in `test/must-run.json` and fail under `VYRE_MUST_RUN=1`. Why: a skip hides a red. Enforced: preflight rule T1, `scripts/test-counts.mjs` with `VYRE_MUST_RUN`.
7. **Zero failing tests for a release.** There is no "known failure" list: a red is fixed, never carried. App type errors count wherever they are. Why: owner ruling of 10 Oct 2026. Enforced: preflight rules T2 and T3, the `node.yml` shards, `test-sweep.yml`.
8. **A test, a guard or the test machinery is never deleted by accident.** Deleting one needs `[delete: why]`. Why: a merge once dropped the headless Chrome helper. Enforced: preflight rule D1.
9. **Real data before merge.** Anything that talks to Claude Code or a network is exercised for real once, not only against a fake. Why: a fake proves the logic, not the integration. **Review only**; fakes are reached through `VYRE_CLAUDE_BIN`, `VYRE_SSH_BIN`, `VYRE_OPEN_BIN` and `VYRE_HANDS_BIN`.
10. **Tests that start a real daemon run on a test box or a runner, never on a Mac.** Preflight refuses to run tests on macOS and offers `--static` there. Enforced: preflight rule P1.
11. **A guard names its rule in its message.** Fix the cause, never loosen the guard. A ratchet list only shrinks. Enforced: preflight rule R1 (`scripts/team/ratchets.mjs`), `test/ratchets.test.js`.
12. **The golden decisions are refreshed only in CI.** `kernel/golden/golden.json`, `allow.json` and `presence.json` are written by the `golden-refresh` workflow (push a commit whose message contains `[golden-update]`), not by hand on a test box, whose answers differ from CI's. A widening needs a written ruling. Enforced: `kernel/golden/allow.test.js`, `kernel/golden/golden.test.js`, `test/golden-widenings.test.js`, `.github/workflows/golden-refresh.yml`.
13. **A seam has a contract test.** Every file in `test/contracts` is a guard for both sides of its seam. Enforced: preflight runs them all.
14. **Performance is measured.** `npm run perf-check` is part of CI. Enforced: `.github/workflows/perf-idle.yml`, `runner-perf.yml`.

## Releases

1. **A release is signed, and only the `release` environment holds the key**; the pinned public key is checked and the lineage verified. Why: an update must come from us. Enforced: `test/release-key.test.js`, `test/sign-manifest.test.js`, `test/release-lineage.test.js`, `test/release-verify-workflow.test.js`, `test/release-workflow.test.js`, `.github/workflows/release.yml`, `release-verify.yml`. Review the diff of any signing file before approving the environment.
2. **The release is built from what the tests proved.** The dist is checked, the served files are checked, and the package contains what the box and the image need (including the golden dump). Enforced: `test/check-release-dist.test.js`, `test/check-served.test.js`, `test/package-files.test.js`, `test/golden-pack.test.js`, `test/box-pack-covers-dockerfile.test.js`.
3. **A release counter and a bump script, not a hand edit.** Enforced: `test/release-counter.test.js`, `test/bump-version.test.js`, `test/patch-release.test.js`.
4. **Migrations released are frozen** (see Architecture rule 11); after a release, record them with `node scripts/record-migrations.mjs`. Enforced: `test/migrations-append-only.test.js`.
5. **Zero failing tests** (see Tests and CI rule 7), no "known failures" in the release notes. Enforced: preflight T2, T3.
6. **Every bug is a GitHub issue** in `vyre-ai/vyre` (label `bug`, with a milestone); a security bug goes to a private advisory, never a public issue. Why: one list of what is broken, and nothing sensitive in public. **Review only.**
7. **Known gaps are written down, not hidden.** What a release does not do is in `docs/known-gaps.md` and the roadmap is kept true. Why: the README and the docs tell the truth about the release. Enforced: `scripts/docs-check` (links and stale mentions); the content is **review only**.
8. **The install proof runs on a real install** before a release is called ready: a fresh machine, the real installer, the real onboarding. Why: green unit tests did not catch a failed first install. Enforced: `.github/workflows/install-proof.yml`, `packaged-boot.yml`, `matrix.yml`, `journeys.yml`.

## Git and commits

1. **Conventional commits, one concern each**: `feat:`, `fix:`, `refactor:`, `docs:`, `test:` (also `ci:`, `security:` where the history uses them). Why: a readable history. **Review only.**
2. **Every code change lands in `CHANGELOG.md` in the same commit**, under `## Unreleased`, in plain sentences that say what changed and why; a new dependency says why it is worth having. Why: the changelog is the release notes. **Review only** (the docs site shows it as the Changelog).
3. **Commit by path** (`git commit -m "..." -- <paths>`) so parallel sessions never sweep up each other's files. A pathspec guards the index but not a shared append-only file such as `CHANGELOG.md`. **Review only.**
4. **Credit the repository owner only.** No `Co-Authored-By: Claude`, no "Generated with Claude" line, no session trailer in any commit, merge, pull request or release note. Why: owner ruling. Enforced: preflight rule G3.
5. **Never `git stash`, force-push, amend a pushed commit or `--no-verify`.** Use a WIP commit or a second worktree. Why: the stash stack is shared across worktrees; the others rewrite history others rely on. **Review only.**
6. **Generated files are not committed by hand**; the merge queue regenerates them. Enforced: preflight rule G1. No conflict markers: rule G2.
7. **Rulings are visible in the commit.** `[kernel +N: why]` for kernel growth, `[ratchet +N: why]` for a growing list, `[reviewed: trust]` for security paths, `[delete: why]` for removed test machinery, `[refactor]` for a behaviour-free change, `[golden-update]` to refresh the golden decisions in CI. Enforced: preflight rules K1, R1, R2, D1, T5.
8. **Land through the queue.** Run `node scripts/team/preflight.mjs` on a test box before queueing work (`--static` is all that runs on a Mac). Edits in another team's paths (`scripts/team/owners.json`) are warned: the two ends of a seam talk first. Enforced: preflight, `.github/workflows/merge-queue.yml`.

## Keeping this file true

When a rule is added, changed or retired, change it here in the same commit as the guard. A rule in this file without a guard and without the words "review only" is a bug. A new guard test names its rule in its first comment so it can be listed here.
